# 本地演示前端

2026-10-22：当前使用虚拟机基础设施，运行 `scripts/start-vm-demo.ps1` 即可启动本机演示。RAG 和 Redis 已启用，详见 `docs/vm-deployment.md`；下文原本机 RAG 关闭记录属于历史验证。

原生 JavaScript / CSS + Node.js 本地静态服务和流式代理，无第三方依赖，无需 npm install 或打包。

## 启动

先按项目 `.local-run/README.md` 启动 PostgreSQL、认证 Redis（16380）、Java（8080）、Python（8000）。项目根目录执行：

```powershell
.\scripts\start-frontend.ps1
```

打开 http://127.0.0.1:5175。或进入 frontend 执行 `npm start`；Ctrl+C 停止前端。可与勤工助学的 5174 / 8081 同时使用。

## 演示路径

1. 先用 `.local-run/login-accounts.txt` 中的账号密码登录，再点击“我的订单到哪了”：创建真实 thread，调用 Java SSE，展示订单查询结果；右侧另行查询真实订单。
2. 继续问“它能退款吗”，演示同一 thread 多轮对话。退款意图不自动沿用历史订单号，按后端规则补充。
3. 新建会话，点击“申请订单退款”，展示 A1001 的明确确认卡片。点击取消可演示 interrupt/resume，而不修改订单。A1002 为已支付未发货，当前后端规则允许取消但不允许退款。
4. 只有明确点击确认才提交 approved=true；退款申请受理不代表退款到账。Redis 未配置时，后端会拒绝执行，前端显示失败/结果未确认，不展示虚假成功。
5. 点击政策问题：RAG 可用时展示返回来源；当前本地 RAG 未启用时展示后端真实降级回答。前端不内置假政策或假业务回答。

## 数据与边界

- 聊天、订单、确认操作统一通过 Java；Python 仅额外提供只读健康状态。后端模型密钥和内部服务令牌不传入浏览器。
- 代理只绑定 127.0.0.1，只转发浏览器的 Authorization，忽略浏览器身份头与内部服务令牌，并限制允许路由和同源访问。登录与鉴权由 Java Spring Security 执行；本机入口仍未配置生产 HTTPS。
- JWT 仅保存在 sessionStorage；退出成功后清除，刷新通过 /auth/me 验证。展示历史按 tenantId/userId 分开存储。每个浏览器会话保存服务端 thread_id；消息展示历史保存在 localStorage（最多 20 个会话），不是从服务端回查。清浏览器数据会丢展示历史，但不会删除 PostgreSQL checkpoint。
- 流式协议以业务 result / approval_required 和 done 判断结果；HTTP 200 不表示成功。断流、error、未知响应不会自动重发，避免重复操作。
- 待确认卡片、确认决定及幂等键在提交前持久化；超时或失败后保留原决定、原幂等键，禁止切换决定重试。最终能否恢复由服务端 checkpoint / 幂等记录决定。
- Web Locks 限制同一浏览器多标签页同时操作同一会话；不替代服务端跨客户端并发控制。刷新中的普通请求不会自动续传，先核实状态。
- 右侧执行记录来自实际 SSE 公开事件，不伪造模型思维链或内部节点执行记录。健康“已连接”只代表接口可达，不代表模型、退款等全链路都可用。
